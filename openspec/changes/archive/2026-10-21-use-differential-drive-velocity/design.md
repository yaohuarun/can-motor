# Design

## Context

动机见 proposal.md。现有 `motor_control.py` 在 `main` 中解析左右轮 rpm，再经 `wheel_speed_raw` 乘 `GEAR_RATIO=15.75` 和方向系数，交给 `speed_raw` 编码；最高转速先量化到 0.1 rpm。external/direct 共用目标值但帧格式不同。`test_protocol.py` 覆盖帧及速度，`test_startup_only.py` 用模拟总线验证全程零速。当前没有主规格文件或 ROS 2 包。

## Goals / Non-Goals

**Goals:** 在现有编码链前增加可独立测试的车体到轮端转换，明确几何单位、符号和兼容性，保证两种控制模式的目标一致。

**Non-Goals:** 不新增 ROS 2 依赖、节点、cmd_vel 订阅、里程计、动态速度更新、几何参数配置或闭环控制；不修改反馈速度单位和 CAN 协议。后续实车反馈要求默认启动观察改为5秒，默认方向改为左−1、右+1。

## Decisions

1. 使用固定 SI 常量 `WHEEL_DIAMETER_M=0.254`、`TRACK_WIDTH_M=0.420`，保留现有减速比。纯函数接收 v、ω 并返回左右轮端 rpm：`left=(v-0.21*ω)*60/(π*0.254)`，`right=(v+0.21*ω)*60/(π*0.254)`。不直接在帧构造中混算几何、方向和比例，以免重复减速或混淆物理轮速与安装符号。
2. 替换两个旧参数，新参数默认 0。相较兼容两套输入，这使目标来源唯一；旧命令明确报错，迁移在 README 说明。`--max-rpm` 仍必填且表示电机轴最高转速，不改成车体速度上限。
3. 复用 `wheel_speed_raw`、`speed_raw` 与配置帧量化基准，安装方向在差速之后应用。保持超速拒绝，避免单轮限幅改变曲率或整体缩放改变目标速度；对输入及中间结果检查有限性，将算术溢出转换为清晰参数错误。
4. `--startup-only` 在目标换算与校验前将有效目标置零，沿用现有忽略速度行为，包括可解析但超速或非有限的目标；无法解析的字符串仍由 argparse 拒绝。正常模式检查有限性及速度上限。诊断输出只显示实际零速，不误报为执行非零请求。
5. 转换发生在打开 CAN 接口之前，两种模式共享同一对 raw 值。预览输出 v（m/s）、ω（rad/s）、轮端 rpm、电机轴 rpm 和现有帧数据。保持运行状态机、故障处理、停止批次和方向覆写参数。

## Risks / Trade-offs

- [旧脚本失效] → 提供旧 rpm 到新参数的迁移公式，更新 README 全部控制示例及测试调用。
- [镜像安装或轮距测量偏差导致实际方向/转弯误差] → 记录轮距为两轮中心间距；使用既有方向参数，实物架空确认，软件测试不宣称实车已验证。
- [转弯比同一线速度的直行更容易超速] → 每轮分别校验并保留报错，不静默调整用户目标。
- [浮点边界及量化误差] → 比较电机轴换算值与量化后的最高转速；只在既有协议编码阶段取整，边界及溢出均测试。
- [启动默认值和方向与实车不符] → 按用户后续要求统一默认启动观察为5秒，将原左+1、右−1反转为左−1、右+1，并更新文档及报文测试；命令行显式值仍覆盖默认值。

## Migration Plan

同时交付参数替换、测试和 README 更新。旧轮速 nL、nR（rpm）对应 `v=πD(nL+nR)/120`、`ω=πD(nR−nL)/(60B)`，其中不含安装方向系数；例如左右轮端均 10 rpm 对应 v≈0.132994889 m/s、ω=0。保持原最高转速及硬件配置参数。

先运行无硬件单元测试与两种模式预览，再由使用者架空确认前进与原地左转。回滚时同时恢复旧参数解析、测试和文档，不涉及持久化数据迁移。
